# GSC 後端與網域驗證

**日期**：2026-10-02
**操作者**：Codex

## 變更內容
- 新增 `integrations` app，實作 GSC OAuth authorize／callback、連線狀態、property 選擇、資料同步、查詢與斷線 API。
- 新增加密 token 儲存、一次性 OAuth state，以及日維度 Search Analytics 資料表。
- GSC `siteOwner` property 涵蓋網站專案 hostname 時，建立或續期既有 `VerifiedDomain(method=gsc)`；其他權限只可讀資料。
- 正式 callback 預設為 `https://ars.clouda.dpdns.org/api/integrations/gsc/callback`，同步環境範本與 Kubernetes 設定。
- 更新 OpenAPI／TypeScript 產物、模組文件、競賽內容文件與專案記憶。

## 原因
會員需要把 Search Console 的搜尋曝光資料與網站專案對接，並以 Google 已確認的 owner 權限作為額外網域所有權證據，同時維持 Argus 掃描授權和 GSC 資料語意的邊界。

## 影響範圍
- 新增 Google 外部 API 呼叫與三個資料表；正式環境需設定 GSC OAuth Client ID／Secret 並在 Google Cloud Console 登記完全一致的 callback。
- 未設定憑證時 authorize API 回 503，不影響既有掃描與報告功能。
- 斷線會刪除本地 GSC 指標，但不撤銷過去已建立且仍在 TTL 內的 VerifiedDomain；網域驗證仍依既有到期規則失效。

## 驗證方式
- 執行 integrations 單元測試、完整後端測試、ruff、Django check 與 migration drift check。
- 重新產生 OpenAPI 與 TypeScript 型別，執行前端 lint／typecheck／unit tests。
- 以測試資料驗證 owner scoping、一次性 state、token 不明文落庫、siteOwner／siteFullUser 邊界與日資料 upsert。
